# 차단 사건 대시보드

Codex 플러그인 훅이 멈춘 전송과 응답 표시 뒤 탐지를 이 PC의 브라우저에 실시간으로 보여준다. 훅이 남긴 `events.sqlite3`를 읽기 전용으로 읽는다.

## 실행

플러그인이 켜져 있으면 직접 실행할 필요가 없다. 세션이 시작되거나 사용자 입력이 멈출 때 훅이 서버를 확인하고, 꺼져 있으면 백그라운드로 띄운다. 주소는 Codex의 `PII 보호 켜짐` 문구와 차단 메시지에 함께 표시되며 `http://127.0.0.1:8787`이다. 브라우저를 자동으로 열지는 않는다.

- 서버는 Codex를 종료해도 남고, 다음 세션은 떠 있는 서버를 그대로 쓴다. 재부팅이나 수동 종료, 플러그인 업데이트·제거 때 멈춘다. 업데이트 뒤에는 다음 세션이나 입력 차단 때 새 버전이 뜬다.
- 서버 시작에 실패해도 차단 판단은 바뀌지 않고, 메시지에서 주소만 빠진다.
- 파일·명령 결과의 차단 문구에는 주소를 넣지 않는다. 이 문구는 사용자가 아니라 LLM에게 전달된다.
- 끄기: Codex 실행 전에 `export PII_DASHBOARD_PORT=off`, 다른 포트는 같은 변수에 포트 번호를 넣는다.
- 종료: `kill $(lsof -nP -t -iTCP:8787 -sTCP:LISTEN)`

직접 실행도 할 수 있다. 표준 라이브러리만 쓰므로 설치할 것이 없다.

```zsh
cd dev
python3 -m observability
```

다른 포트나 기록 파일은 `--port`, `--journal`로 지정한다. 기본 경로는 `$CODEX_HOME`(없으면 `~/.codex`) 아래 `plugins/data/pii-gateway-codyssey-security/events.sqlite3`다.

## 코드 수정 시

Codex는 플러그인 폴더만 복사해 실행하므로 `launcher/plugin/hook_runtime/vendor/observability/`에 같은 코드가 들어 있다. 원본은 이 폴더이며, 고친 뒤 vendor로 복사한다. 내용이 다르면 테스트가 실패한다. 플러그인을 바꾸면 `plugin.json`의 버전을 올리고 아래 명령으로 다시 설치한 뒤, Codex 시작 화면에서 훅을 다시 승인한다.

```zsh
codex plugin add pii-gateway@codyssey-security
```

## 판정

큰 숫자는 `direction=outbound`이고 `stage=decision`인 멈춘 전송만 센다. `not_sent`만으로 판단하지 않는다. 응답 검사 실패도 `not_sent`로 기록되지만 응답은 이미 화면에 표시된 뒤이기 때문이다.

| 판정 | 기록 | Codex에서 일어난 일 |
|---|---|---|
| 차단 | `block` / `not_sent` | 입력이나 파일·명령 결과를 보내지 않음 |
| 중단 | `mask` / `not_sent` | 입력을 멈추고 가린 문장을 안내 |
| 가림 | `mask` / `forwarded_sanitized` | 파일·명령 결과를 가린 내용으로 바꿔 전달 |
| 실패 | `error` / `not_sent` | 검사를 끝내지 못해 멈춤. 플러그인 `0.2.0-hook.3` 이전 기록은 경로 미상으로 표시 |
| 사후 | `error_code=POST_DISPLAY_FINDING` | 응답이 화면에 표시된 뒤 발견. 막지 못했으므로 큰 숫자에서 제외 |

허용된 전송은 사건 목록에 넣지 않고 운영 현황의 건수로만 표시한다.

## 운영 현황

방향별 검사·통과·마스킹·차단·실패 수와 훅 처리 시간 p50·p95(nearest-rank)를 판단 기록 전체로 계산한다. 응답의 마스킹·차단은 표시 뒤 탐지이며, 처리 시간은 검사 실패를 뺀 훅 내부 시간이다. 규칙 모드 값이므로 모델 추론 성능을 뜻하지 않고, 건수는 탐지 정확도가 아니다.

`마지막 검사 N분 전`은 훅이 마지막으로 기록한 시각이며, 지금 보호가 켜져 있다는 증거는 아니다. 보호 여부는 Codex의 `PII 보호 켜짐` 표시로 확인한다.

## 보이지 않는 경우

대시보드에 없다고 해서 안전하다는 뜻은 아니다.

- 훅을 승인하지 않았거나 플러그인이 꺼져 있으면 기록 자체가 없다. Codex 시작 시 `PII 보호 켜짐` 표시를 확인한다.
- 훅이 비정상 종료했거나 기록에 실패한 경우에는 전송을 막아도 사건이 남지 않는다.
- 다른 PC의 사건은 보이지 않는다. 중앙 수집은 구현되어 있지 않다.

## 범위와 보안

- 서버는 `127.0.0.1`에만 바인딩하고 `Host` 헤더를 검사하며 GET만 받는다. 로그인 기능은 없다.
- PRD §9의 중앙 수집, 대시보드 로그인, SSE, 오프라인 평가 표시는 구현하지 않았다. 일반 서버를 쓸 수 없어 PC 안의 저널을 직접 읽는 구조를 택했고, 이는 "C가 직접 로컬 파일에 접근하지 않는다"는 PRD 항목과 다르다.
- 기록 파일은 SQLite `mode=ro`로만 연다. 저널에 원문이 없으므로 화면에도 유형, 건수, 규칙, 시각 같은 메타데이터만 나온다.
- 외부 글꼴이나 스크립트를 불러오지 않는다.
- 화면은 최근 200건을 보여주고, 합계는 전체 기록을 센다.
