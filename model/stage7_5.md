# 7.5단계: 학습·평가를 고치고 결과를 다시 확인하기

> **7.5단계 오프라인 평가 및 보고서 완료(2026-11-01):** [2차 인수인계서](to_agy_2nd.md)에 따라 동결 서비스 시험(300건)과 공식 Test(`test_track_a`, 28,142건)의 M0·M1 최종 평가, 문서 짝지은 95% 신뢰구간, 오류·잔존·정상 실패 원인 분류, [최종 보고서 v1](report_v1.md) 및 [전체 그래프 18종](graph/README.md) 작성을 모두 완료했습니다. 현재 최종 판정은 `pending_runtime_acceptance`(A 오프라인 수치 게이트 통과, B 운영 인수 전까지 운영 모델 M0 유지)입니다. 최신 요약은 [stage7_5-progress.md](reports/stage7_5-progress.md), [서비스 최종 집계](reports/stage7_5-service-final-v1.json), [공식 Test 최종 집계](reports/stage7_5-official-final-v1.json)를 확인하세요.

작성일: 2026-10-31 · 갱신일: 2026-11-01 · 상태: **7.5단계 오프라인 검증·최종 평가·보고서·그래프 완료 (8단계 B 운영 인수 별도 대기)**

**현재는 M0를 유지합니다.** M1 학습과 초기 평가 결과 파일은 있지만, 최종 검증 완료로 승인할 수 없는 문제가 발견됐습니다. 먼저 평가 방법을 고친 뒤 기존 저장본을 확인하고, 필요한 경우에만 다시 학습합니다.

이 문서는 앞으로 할 작업의 기준입니다. 이미 확인한 문제와 근거는 [7단계 검토서](reports/stage7-review-v1.md), 이전 실행의 수치는 [M1 잠정 결과](reports/m1-training-summary.md)에 있습니다. 원래 8단계는 유지하고 7과 8 사이에 보완 단계를 추가합니다.

## 1. 왜 필요한가요?

모의고사 채점기와 시험 절차를 먼저 고친 뒤 성적을 비교하는 작업이라고 생각하면 됩니다.

| 발견한 문제 | 쉬운 설명 | 현재 판단 |
|---|---|---|
| 학습·추론 분할 불일치 | 공부할 때와 실제 답을 찾을 때 문장을 나누는 방법이 다름 | 공통 분할 연결·검증 필요 |
| 미완료 검사를 빈 예측으로 채점 | 시험을 끝내지 못한 것을 “찾을 정보가 없음”으로 기록 | 평가기 수정 필요 |
| 서비스 시험셋 300건 미검토·미동결 | 정답의 의미를 사람이 확인하기 전에 점수를 계산함 | 기존 v1은 탐색/회귀 자료로 보존 |
| epoch별 dev 선택 근거 없음 | 어떤 중간 저장본이 새 문제를 잘 푸는지 비교한 기록 부족 | 저장본·로그 회수 후 dev 평가 |
| 오차단 및 중요 유형 퇴행 | 정상 문서 차단이 1→8건, 계좌·카드 미탐도 증가 | 현재 M1 교체 거절 |

loss가 8.61에서 1.22로 줄었다는 기존 보고만으로 과적합이나 추가 epoch 필요 여부를 판단할 수 없습니다. 시작·끝 두 값으로 학습 곡선을 그리지 않습니다.

## 2. 작업 순서와 완료 기준

아래 7.5단계 오프라인 항목(7.5-1 ~ 7.5-6)은 모두 코드·명령·결과·해시 증거와 함께 **완료**되었습니다. (단, 8단계 B 런타임 분할기 채택 및 운영 인수는 별도 대기 상태입니다.)

시험 준비에는 선행 조건이 있습니다. **7.5-5의 새 holdout 작성·사람 검토·동결은 7.5-3의 후보·임계값 선택과 추가 학습 전에 마칩니다.** 7.5-5에 적힌 실제 최종 평가는 모든 선택이 끝난 뒤에만 실행합니다. 코드 수정·기존 실행 증거 회수는 시험 검토를 기다리지 않고 진행할 수 있습니다.

### 7.5-1. 기존 실행의 증거부터 보존합니다

- [x] 서버 실행 당시 소스·Git 커밋, Python/패키지 환경, 실제 `TrainingArguments`, `trainer_state.json`, 학습 로그를 회수합니다. ([stage7_5-recovery-v2.json](reports/stage7_5-recovery-v2.json))
- [x] epoch 1·2 저장본 및 최종 가중치·config·tokenizer의 파일 목록과 SHA-256을 기록합니다. 기존 모델 디렉터리를 덮어쓰지 않습니다.
- [x] 5,000건 표본의 원본 ID, 고유 문장 수, 분야·유형 분포, 원본/변환 파일 해시, 선정·거절 규칙을 확인합니다.
- [x] 보고서의 batch 4·누적 2·LR `2e-5`와 제출 코드의 batch 8·누적 1·LR `3e-5` 중 실제 실행 설정을 증거로 확정합니다. (복구 소스 기준 batch 8·누적 1·LR `3e-5` 확인, 별도 인자 파일 부재 명시)

현재 표본 코드는 `random.seed(42)` 이후 난수를 사용하지 않고 앞에서부터 변환 성공한 5,000문서를 가져옵니다. 분야·유형 고려 및 중복 제거도 없습니다. 실제 표본과 코드가 같았는지 확인하고 PRD 방식에 맞는지 판단합니다. 전량 후보에 18개 유형이 있다는 사실만으로 실제 5k에도 모두 있다고 가정하지 않습니다.

**완료 증거:** 실행 소스·환경·실제 인자·표본 manifest·저장본 해시가 연결된 실행 이력([stage7_5-recovery-v2.json](reports/stage7_5-recovery-v2.json)). 서버에 없거나 회수하지 못한 항목은 미확인으로 기록합니다.

### 7.5-4. 오차단과 계좌·카드 퇴행 원인을 분석합니다

- [x] 정상 오차단과 중요 유형 미탐을 문서 형식·경계·유형 혼동 등으로 분류합니다. 원인을 추정과 확인으로 나눕니다. ([report_v1.md §4](report_v1.md))
- [x] dev에서 임계값별 정탐·오탐의 절충을 측정합니다. 임계값 상향 시 중요 정보 탐지도 줄 수 있음을 확인합니다.
- [x] 보정만으로 부족한 경우에 한해 정상 예시 혼합·표본 보완·재학습을 별도 실험으로 수행합니다. (공통 분할기 `ko_atomic_suffix_v3` 결합만으로 계좌·카드 퇴행이 해소되고 dev/최종 수치 게이트를 충족해 재학습 없이 완료)

“임계값 0.65~0.7이면 오차단 1% 이하”는 검증되지 않았습니다. 현재 규칙 결합은 모델 탐지에 규칙 탐지를 더하는 방식이며 모델 오탐을 자동 제거하지 않습니다.

**완료 증거:** 오류 분류, 변경 근거, dev 재측정 결과([stage7_5-selection-v1.json](reports/stage7_5-selection-v1.json), [report_v1.md](report_v1.md)). 추가 epoch는 이 근거와 중단 기준을 갖춘 경우에만 선택합니다.

## 3. 최종 판정 기준

| 기준 | 판단 방법 |
|---|---|
| 중요 5종 합산 재현율 | 같은 최종 시험에서 M0 이상 |
| 전체 엔터티 F1 | 같은 최종 시험에서 M0 이상 |
| 정상 오차단 증가 | M0 대비 +1%p 이하. 과거 표본의 1/100 기준에서는 M1 2/100까지이며, 새 시험에서는 새로 측정한 M0 기준으로 계산 |
| 중요 유형별 퇴행 | 계좌·카드 등 특정 유형의 악화를 합산 개선으로 숨기지 않음. 원인 미해소 시 교체 보류 |
| 실행·시험의 유효성 | 공통 분할, 완결된 검사, 사전 동결, dev 선택 절차, 파일/모델 확인값 확보 |
| 운영 인수 | B의 실제 로딩·지연·메모리·통합·복구 증거 필요. 확인 전 미확정 |

PRD §10의 검사 목표는 예열·동시 1·2,000 코드포인트 이내에서 클라이언트 측 **p95 ≤ 500ms/회**입니다. 총 평가 시간÷문서 수는 평균이며 이 목표의 증거가 아닙니다. 이전 인계서의 30ms·4GB를 확정된 PRD 기준으로 사용하지 않습니다.

## 4. 작업 분담과 실행 범위

| 담당 | 작업 |
|---|---|
| Codex 주도 권고 | 핵심 코드·평가 절차 수정, 회귀 검증, 수치 검토, 보고서·그래프 |
| Agy 보조 가능 | 접근 가능한 기존 서버에서 로그·저장본 회수, 검증된 명령으로 GPU 평가 실행 |
