# 2단계: 데이터 다운로드와 검증

검사 대상은 [1단계에서 고정한 파일](../configs/assets.lock.json)의 `train`, `dev`, `test_track_a`입니다. 원본 파일은 Git에서 제외되는 `model/.cache/`에 저장하고, 검사 결과만 `model/reports/`에 보관합니다.

아래 명령은 저장소 루트에서 실행합니다. 이 단계는 Python 표준 라이브러리와 파일 전송용 `curl`을 사용하므로, GPU나 PyTorch 설치 없이 실행할 수 있습니다.

## 현재 작업과의 관계 — 7.5단계

이 문서는 2단계 다운로드·구조 감사의 재현 안내입니다. 이후 초기 M0/M1 실행 기록이 추가됐고, 현재는 [7.5단계](../stage7_5.md)에서 평가 경로와 실행 증거를 보완합니다. 원본 감사 통과가 실제 학습·최종 평가 승인과 같은 것은 아닙니다.

원본 train/dev/test에는 정상 문서가 0건이며 dev/test의 PERSONAL_ATTRIBUTE gold도 0건입니다. 정상 문서 조정 자료와 최종 시험은 별도로 준비합니다. 실제 5k 표본은 분야·유형·고유 문장 수·원본 ID·파일 해시를 확인하고, 현재 실행기의 선착순 변환 성공 5k 방식을 PRD에 맞게 검토해야 합니다. 기존 원본·분할·감사 JSON은 보존합니다.

## 1. 작은 예시로 검증 코드를 테스트하기

```bash
python3 -m unittest discover -s model/tests -v
```

테스트는 임시 폴더의 합성 자료만 사용합니다. 인터넷과 GPU를 사용하지 않습니다. 테스트 클래스는 pytest에서도 실행할 수 있습니다.

잘못된 정답 위치·이모지·조사·반복된 문자열·중복·분할 간 겹침·손상 파일을 제대로 발견하는지 확인합니다. 숫자 점수로 모델의 실력을 측정하는 테스트는 아직 아닙니다.

## 2. 고정 데이터 받기

```bash
python3 -m model.data.download
```

기본 저장 위치:

```text
model/.cache/k-pii-bench/844f92f7beba98fa964f957ba324017e82451701/data/
├── train.jsonl
├── dev.jsonl
└── test_track_a.jsonl
```

다운로드 중에는 `.part`라는 임시 이름을 사용합니다. 파일 크기와 SHA-256이 원본 기준과 일치해야 최종 파일 이름으로 등록합니다. 도중에 연결이 끊기면 같은 명령으로 이어받기를 시도합니다. 이미 받은 정상 파일은 다시 받지 않습니다.

기존 최종 파일의 확인값이 다르거나 임시 파일이 손상된 경우에는 실패로 표시하고 보존합니다. 손상된 내용을 정상 데이터로 사용하거나 기존 파일을 자동으로 덮어쓰지 않습니다. 원본과 URL·리비전이 다른 설정도 거절합니다.

## 3. 전체 자료 검사하기

```bash
python3 -m model.data.audit --output model/reports/data-audit-new.json
```

검사는 한 줄씩 읽으면서 모든 레코드를 확인합니다. 결과는 다음을 포함합니다.

| 검사 | 확인할 내용 |
|---|---|
| 원본 파일 확인 | 파일 크기와 SHA-256이 고정 기준과 같은지 |
| 문서 구조 | 필수 항목의 존재·자료형, JSON·UTF-8 오류 |
| 정답 위치 | 시작·끝 위치가 유효하고 `text[start:end]`가 정답 문자열과 같은지 |
| 개인정보 종류 | 고정한 18개 유형에 포함되는지, 유형별 엔터티 수·문서 수 |
| 분야·길이 | 12개 분야의 문서 수, 문장 길이, 16,000자를 넘는 문서 수 |
| 정답 중복·겹침 | 같은 정답이 반복되거나 두 정답의 위치가 겹치는지 |
| 문서·문장 중복 | 같은 ID나 동일 문장이 반복되는지 |
| 중복 문장의 정답 | 동일 문장의 개인정보 종류·위치가 서로 일치하는지 |
| 문장 틀 분리 | 분할 간 동일 `template_id` 또는 동일 `template_text`가 있는지 |
| 원본 토큰 자료 | 토큰·BIO·위치 배열 길이, BIO 이름, 토큰 위치 범위·순서 |
| 공개 통계 대조 | 분야별 문서 수와 문장 틀 개수가 원본 통계와 같은지 |

다른 분할의 중복은 문장과 문장 틀의 실제 내용을 내부적으로 비교해 찾습니다. 비교용 문장별 해시는 메모리에서만 사용하고 보고서에 내보내지 않습니다.

보고서에는 원문 문장·이름·전화번호·문서 ID를 넣지 않습니다. 문제 유형·분할·행 번호와 통계만 기록합니다. 공개 데이터 파일 전체의 SHA-256은 어느 원본을 검사했는지 식별하기 위해 기록합니다.

이미 있는 보고서는 덮어쓰지 않습니다. 변경 후 다시 검사할 때는 `data-audit-v2.json`처럼 새 이름을 지정합니다. 보고서에는 실행한 Python 버전, 검증 코드·자산 기준·원본 통계 파일의 SHA-256도 기록합니다.

현재 전체 검사의 기준 보고서는 [data-audit-v2.json](../reports/data-audit-v2.json)입니다. `v1`은 중복 발견 직후의 최초 결과이고, `v2`는 중복 문장 정답 일치 여부와 없는 라벨의 0건 표시를 추가한 결과입니다. 쉬운 해설은 [결과 요약](../reports/data-audit-summary.md)에 있습니다.

## 결과를 읽는 방법

| 상태 | 뜻 | 다음 행동 |
|---|---|---|
| `passed` | 구현한 구조·위치·분포·중복 검사를 통과 | 다음 단계의 학습 형식 변환 준비 |
| `needs_review` | 정답 겹침이나 같은 분할 내 문장 중복 등 검토할 항목 존재 | 원인을 확인하고 처리 기준을 기록 |
| `failed` | 잘못된 위치·파일 손상·분할 간 겹침 등 오류 존재 | 원본·검증 기준·수정 방법을 확인한 뒤 진행 |

같은 학습 분할에서 여러 문장이 같은 문장 틀을 사용하는 것은 정상입니다. 다른 분할에 같은 문장 틀이 나타나는 것은 학습과 시험이 겹치는 문제이므로 구분합니다. 겹치는 정답과 중복 문장은 조용히 삭제하지 않고 검토 대상으로 남깁니다.

문장 수와 분야별 개수는 다운로드한 전체 파일에서 다시 계산합니다. 오류 예시는 기본 20건까지만 저장하지만, 오류 건수는 전체 자료에서 계속 셉니다.

## 이번 검사로 알 수 없는 것

정답 위치와 문자열이 일치해도 그 정보의 유형을 의미상 올바르게 분류했는지까지 보장하지는 않습니다. 원본 BIO 정답과 문자 엔터티 사이의 완전한 의미적 정합성, GLiNER 토큰 변환·길이 처리, 모델의 실제 탐지 성능도 이 단계의 검증 대상과 구분합니다.

시험셋은 파일 구조와 정답 품질만 검사합니다. 모델 예측이나 점수를 계산하지 않으며, 시험셋 내용으로 학습 설정·임계값을 고르지 않습니다. 학습용 5,000건 표본 선정도 후속 단계입니다.
