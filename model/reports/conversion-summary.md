# 3단계 결과: 변환 도구 구현·검증 완료, 학습 자료 호환성 해결 필요

아래 §1~5는 **3단계 기본 분할 진단 당시**의 기록입니다. §6은 이후 후보 진단이며 실제 예측·운영 연동 완료를 뜻하지 않습니다. 현재는 초기 M0/M1 실행 기록 이후 [7.5단계 보완](../stage7_5.md)이 필요합니다.

**3단계 당시 기본 설정으로는 PRD의 5,000건 학습으로 넘어갈 수 없었습니다.** 정확한 정답을 모두 보존한 train 문서는 2,635건이며, 같은 문장을 한 번만 세면 2,615건입니다. 상태는 `blocked_compatibility`입니다.

변환 코드, 거절 기록, 실제 토크나이저와 GLiNER 학습 배치 형식 검증은 준비했습니다. 아래 진단용 자료를 정식 학습 표본이나 공식 평가셋으로 사용하지 않습니다.

## 1. 2단계에서는 정상이었는데 왜 변환이 막히나요?

2단계는 원본 문장의 글자 위치와 정답 문자열이 일치하는지 확인했습니다. 3단계는 그 정답을 모델이 읽는 단어 위치로 정확히 표현할 수 있는지 확인합니다. 서로 다른 검사입니다.

예를 들어 `김가상에게`에서 정답은 이름 `김가상`입니다. 현재 B의 기본 GLiNER splitter는 전체를 한 단어로 읽습니다. 이 단어의 일부만 정답으로 가리키는 word-span이 없으므로, 원본 정답이 올바르더라도 그대로 변환할 수 없습니다.

조사까지 정답을 늘리거나, 이름 정답을 지우거나, 정답 위치를 보고 학습 자료에서만 단어를 쪼개지 않았습니다. 어느 정답이든 표현되지 않으면 문서 전체를 거절하고 사유를 기록했습니다.

## 2. 전체 30만 건 실제 변환 결과

| 분할 | 원본 문서 | 모든 정답 보존 가능 | 거절 | 가능한 문장 중 고유 문장 |
|---|---:|---:|---:|---:|
| `train` | 243,711 | 2,635 | 241,076 | 2,615 |
| `dev` | 28,147 | 577 | 27,570 | 570 |
| `test_track_a` | 28,142 | 120 | 28,022 | 119 |

실제 고정 토크나이저·라벨 prompt·B의 512 서브토큰/384단어/12단어 스팬 한도를 적용했습니다. 전체 실행은 로컬에서 약 27.2초였습니다. GPU 추론 속도나 탐지 성능 측정이 아닙니다.

| 분할 | 첫 거절 사유: 정답 경계 불일치 | 첫 거절 사유: 12단어 스팬 초과 |
|---|---:|---:|
| `train` | 239,561 | 1,515 |
| `dev` | 27,154 | 416 |
| `test_track_a` | 27,343 | 679 |

한 문서에 문제가 여러 개 있어도 위 표에서는 처음 확인한 사유 하나로 거절 문서를 셉니다. 상세 JSON에는 모든 정답을 개별 검사한 유형별 수치도 있습니다.

| 분할 | 경계·폭이 맞는 정답 | 단어 경계 불일치 정답 | 경계는 맞지만 12단어 초과 정답 |
|---|---:|---:|---:|
| `train` | 386,170 | 720,339 | 6,071 |
| `dev` | 37,982 | 85,121 | 416 |
| `test_track_a` | 36,361 | 84,017 | 798 |

문서에 있는 정답 한 개라도 보존할 수 없으면 문서 전체를 거절하므로, 개별 정답이 경계에 맞는 것과 그 문서를 학습 자료로 쓸 수 있는 것은 다릅니다.

변환 가능한 train 부분에는 다음 7개 유형의 정답이 남지 않았습니다: `KR_DRIVER_LICENSE`, `KR_PASSPORT`, `KR_NHIS`, `KR_VEHICLE_PLATE`, `USERNAME`, `PERSONAL_ATTRIBUTE`, `URL`.
따라서 작은 부분집합으로 임의 축소해서 학습하면 자료 수뿐 아니라 유형별 대표성도 PRD의 의도와 달라집니다. 5,000건 표본을 선정하거나 학습을 시작하지 않았습니다.

## 3. 무엇을 구현하고 검증했나요?

- 문자 끝 제외 위치를 단어 끝 포함 위치로 정확히 변환하고, 원문 위치로 역변환하는 검증을 구현했습니다.
- 한국어 조사·공백·반복 문자열·이모지·결합 문자·최대 스팬·부분 정답 창·라벨 순서·실패 기록 테스트를 작성했습니다.
- 전체 기본 테스트 104개가 통과했습니다. 데이터·네트워크·GPU 없이 실행하는 테스트입니다.
- 실제 GLiNER 0.2.29·Transformers 4.57.3·DeBERTa 토크나이저로 합성 경계 사례 6개를 검증했습니다.
- 실제 GLiNER collator가 고정 18개 라벨을 유지하고, 끝 포함 위치·같은 위치의 여러 라벨·정답 없는 예시를 CPU 텐서로 정확히 만드는 것을 확인했습니다.
- 모델 가중치, 가짜 모델 패키지, 가짜 예측 함수를 만들지 않았습니다. 토크나이저·배치 처리기와 B의 기존 계획 함수만 사용했습니다.
- 원본 3개 데이터 파일의 크기·SHA-256을 다시 확인한 뒤 진단 출력을 만들었습니다. 원본과 공식 분할은 바꾸지 않았습니다.
- 모든 원본 문서에 변환/거절 기록이 있고, 문서 수와 원본 정답 개수의 합계가 보존됨을 확인했습니다.
- 변환·실제 런타임 검사 프로세스는 네트워크 연결을 차단했고, 연결 시도 0회를 확인했습니다.
- Mac CPU 검증용 격리 환경의 패키지·확인값을 기록했고 `pip check`도 통과했습니다. GPU 서버의 설치 환경은 변경하지 않았습니다.

토크나이저 초기화에서 byte-fallback 및 upstream 정규식 경고가 관측되었습니다. 기존 B 설정을 유지했고, 탐지 품질 영향이 해결되었다고 판단하지 않습니다.

## 4. B와 맞춰야 할 결정과 다음 작업

권장 방향은 **정답을 보지 않고 원문만으로 결정되는 한국어 분할 방식을 A와 B가 함께 정하는 것**입니다. 형태소 기반 분할 같은 후보를 train/dev에서 검토할 수 있지만, 당시에는 특정 방식의 변환 가능량을 확인하기 전이었습니다. 이후 후보별 진단 수치는 §6에 기록했고 실제 공통 예측 연동은 7.5단계에서 검증합니다.

| 공동 확인 항목 | 필요한 이유 |
|---|---|
| 동일한 단어 분할·원문 위치 복원 | 학습과 실제 검사 서버가 같은 정답 경계를 사용해야 합니다. |
| 조사·숫자·기호·혼합 언어·긴 정답 처리 | 한 종류의 경계만 고치고 다른 유형을 망가뜨리지 않아야 합니다. |
| 12단어 스팬·384단어·512 서브토큰과 겹침 창 | 토큰 수가 늘어나도 원문과 정답을 잘라 버리지 않아야 합니다. |
| tokenizer·preprocessing·라벨 매핑 버전 | B가 같은 설정을 로딩하고 결과를 재현해야 합니다. |
| M0 기준선과 M1에 동일한 절차 적용 | 분할 설정 변경의 효과를 추가 학습 효과로 오해하지 않아야 합니다. |

분할 방식이 합의되면 전체 변환·역변환·커버리지를 다시 검증하고, 유형별 분포를 확인한 뒤 5,000건 표본을 선정합니다. M0 기준선도 같은 방식으로 측정합니다. 공식/독립 시험셋은 설정 선택에 사용하지 않습니다.

현재의 2,615건 부분집합으로 요구사항을 줄이거나 기존 B의 운영 splitter를 바꾸는 결정은 하지 않았습니다. 두 작업 모두 단순한 파일 형식 변환을 넘어 지원 범위와 평가 조건에 영향을 줍니다.

## 6. 후속 해결안: 한국어 분할기 후보군 진단 결과 (2026-10-31 갱신)

A 파트는 원문만을 보고 결정하는 순수 한국어 분할기 후보 4종을 개발하고 K-PII-Bench 전체 train(243,711건) 및 dev(28,147건)에 대해 무손실 거절 정책 하에서 정밀 진단을 수행했습니다 ([상세 JSON](segmentation-diagnosis-v2.json)).

### 분할기 후보별 Train(243,711건) 변환 결과 비교

| 후보 ID | 변환 성공 문서 | 변환 비율 | 고유 문장 수 | 소실된 유형 (0개 보존) | 주요 거절 사유 |
|---|---:|---:|---:|---|---|
| `whitespace_default_v1` (기존) | 2,635 | 1.08% | **2,615** | 7종 (`URL`, `USERNAME`, `KR_PASSPORT` 등) | 조사 결합 경계불일치 (239,561건) |
| `ko_script_particle_v1` | 147,405 | 60.48% | **145,511** | 1종 (`URL`) | 경계불일치 71,645, 12단어초과 24,465 |
| `ko_script_suffix_v2` | 204,046 | 83.72% | **201,274** | 1종 (`URL`) | 12단어초과 33,068 (긴 URL 단어분할) |
| **`ko_atomic_suffix_v3` (제안 후보)** | **236,900** | **97.21%** | **233,724** | **0종 (전 유형 보존)** | 경계불일치 6,230, 12단어초과 444 |

- **후보 `ko_atomic_suffix_v3`의 진단 범위**:
  - 원문만으로 URL/이메일을 원자적 단어로 보호하고 한글 조사/접미사를 나누는 후보입니다.
  - 변환 성공 236,900문서/원본 243,711문서 = 97.21%입니다. 고유 문장 233,724개를 원본 문서 수로 나눈 95.90%와 구분합니다.
  - 18종 모두 정답이 남지만 일부 정답은 거절됐습니다. “유형 소실 0”이 “원본 정답 손실 0”이나 “균형 잡힌 5k 표본 확보”를 뜻하지 않습니다.
  - 역변환 실패 0건은 진단 출력의 위치 검증 결과이며 탐지 성능이 아닙니다.
  - 진단 JSON의 `a_b_adopted=false`, `training_ready=false`를 유지합니다. [연동 제안서](../segmentation/README.md)에 실제 예측과 재로딩까지의 연결 조건을 정정했습니다.
  - 후속 작업은 [7.5단계](../stage7_5.md)를 따릅니다. 기존 진단·원본·정답은 변경하지 않습니다.
