| 피드백 | 반영 방법 | 확인 범위 |
|---|---|---|
| 여권 10자리 | 신규 생성기는 `M`+숫자 8자리 또는 `M`+숫자 3+영문 1+숫자 4 형태로 제한 | 총 9자리 생성 회귀 검사 |
| 주민번호 세기/성별 코드 | 실제 생성 연도를 먼저 정하고 1900년대 1/2, 2000년대 3/4를 선택. 유효한 월·일로 생성 | 생성 연도·형식 검사. 실제 발급된 번호임을 주장하지 않음 |
| 운전면허 지역·연도 | 피드백에 맞춰 27을 제외한 선택 지역과 연도 20~25로 합성 범위 제한 | 이번 시험셋의 보수적 생성 정책이며 모든 역사적·예외적 면허의 유효성 판정 규칙은 아님 |

| 전화 국번 | 중간 번호가 2~9로 시작하도록 선택하고 국내·국제·지역 표기를 생성 | 합성 형식 검사. 실제 번호 할당 여부는 확인하지 않음 |
| 받침에 맞지 않는 조사 | 한글 종성 및 숫자·영문 읽기에 따른 조사 선택, 교체 후 모든 gold 위치 역검사 | 은/는·이/가·을/를·과/와 처리. 원문·정답 불일치 0건 |

여권의 두 예시 형식은 [외교부 차세대 여권 안내](https://www.passport.go.kr/home/kor/onlineExperience/index.do?menuPos=61)에서 확인했습니다. 전화 국번은 [전기통신번호관리세칙](https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulId=35486&efYd=0)의 일반 번호 체계와 피드백을 참고한 제한된 생성 정책입니다. 이 생성기는 실제 발급·할당·예외 규정 전체를 검증하는 도구가 아닙니다.

기존 v1 시험셋 재생성 이력을 보존하기 위해 `service_testset_builder.py`의 원래 값 생성 방식은 변경하지 않았습니다. 새 시험셋은 별도 `FreshValues`를 사용하며 알려진 잘못된 형식을 상속해 사용하지 않도록 재정의했습니다.

## 2. 구조·다양성 문제

| 피드백 | 반영 결과 |
|---|---|
| 영문 스키마 라벨 직접 노출 | 성명·연락처·환급 계좌·회신 이메일 등 자연어 항목명으로 교체. 원문에 canonical label 토큰이 없는지 검사 |
| particle 태그 일괄 부여 | 실제 엔터티 끝에 조사가 붙는 서식에만 부여. 괄호 뒤 조사를 직접 결합으로 세지 않음 |
| 장문 한 문장 반복·정답 마지막 편중 | 서로 다른 업무 문장과 앞/중간/뒤의 엔터티 배치로 변경 |
| 실제 창 경계 검사 부재 | 고정 tokenizer·분할·라벨 prompt·한도를 사용하는 planner로 10개 장문에 카드 span이 실제 창 끝을 가로지르도록 구성. 모델 가중치·점수는 사용하지 않음 |
| 정상 100건 획일성 | 업무 날짜, 금액·수량, 일반 명사, 조직명 유사 보통명사, 설정, 코드, 표·목록, 혼합 언어, 일상·업무 문장, 숫자 유사값의 10개 분야로 교체 |
| NRP·개인속성 어휘 반복 | 충분한 어휘 풀에서 비복원 추출. 검토 시 유형 의미·범위도 다시 확인 필요 |

추가로 중요 유형과 서식이 고정되는 배치도 분산했습니다. 각 중요 유형이 여러 서식에 골고루 들어가도록 구성합니다. 장문 경계 구성은 해당 planner에서의 입력 표현 검사이며 실제 탐지 성능을 의미하지 않습니다.

## 3. 재검토 및 동결

수정본은 300건(요청/응답 각 150), 정상 100건, 중요 유형별 gold 30개 이상 및 18종 지원을 기계적으로 확인했습니다. 공식 데이터·기존 서비스 v1과의 겹침 검사도 manifest에 기록했습니다.

초안 파일은 `needs_review`, `frozen=false`로 보존했습니다. 이후 사용자가 **“r2 300건 재검토 완료, 동결 승인”**을 명시해 승인 결정·검토자·시점을 별도 기록하고 동결본을 만들었습니다. [동결 manifest](../evaluation/service-holdout-v2-r2.frozen.manifest.json)의 SHA-256은 `26c21a0293ff71c49be9d36ee9749c3d85249f545713c24dcb49027758f7db87`입니다. 최초 피드백의 검토 완료를 자동 승인으로 전환하지 않았으며 수정본에 대한 별도 승인을 받았습니다.

동결 후 별도의 dev 선택을 진행합니다. 최종 시험은 선택이 끝난 뒤에만 평가하며, 결과를 보고 다시 설정을 고르지 않습니다. 동결본 자체를 수정해야 한다면 새 버전·해시·재검토 이력이 필요합니다.
