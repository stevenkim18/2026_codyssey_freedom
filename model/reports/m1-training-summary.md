## 2. 서비스 v1 초안 300건의 잠정 비교

같은 자료 이름·문자 스팬 지표를 사용한 저장 JSON의 비교입니다. **서비스 v1은 전수 미검토·미동결이며 최종 독립 시험으로 승인되지 않았습니다.** 기록의 형식 검증 통과와 평가의 유효성은 다릅니다.

| 지표 | M0 | M1 | 변화 | 잠정 판단 |
|---|---:|---:|---:|---|
| 전체 Precision | 47.69% | 55.98% | +8.29%p | 집계 수치 |
| 전체 Recall | 50.71% | 60.86% | +10.14%p | 집계 수치 |
| 전체 micro F1 | 49.16% | 58.31% | +9.16%p | 기준선 이상 |
| 중요 5종 micro Recall | 51.88% | 61.43% | +9.56%p | 기준선 이상 |
| 중요 5종 micro F1 | 59.49% | 58.06% | -1.43%p | 하락 |
| 정상 오차단 | 1/100 (1%) | 8/100 (8%) | +7%p | 허용 +1%p 초과 |

중요 유형 합산 Recall은 올랐지만 FP가 66 → 147로 증가해 중요 유형 micro F1은 하락했습니다. 기존 문서의 “57.51% → 58.06%, +0.55%p”를 정정했습니다.

### 중요 유형별 근거

| 유형 | Gold | M0 TP / FN | M1 TP / FN | Recall 변화 | F1 변화 |

계좌·카드 미탐 증가는 합산 개선과 별도로 해결해야 합니다. 주민번호는 TP 4 → 29로 늘었으나 표본 gold 42개에 대한 잠정 결과입니다. 원인과 불확실성을 함께 보고해야 합니다.

## 4. 교체 판정과 남은 조건

저장된 [판정 JSON](m1-vs-m0-decision.json)은 `reject`입니다. 이 판정은 B 수용을 미확정으로 두어도 재현됐습니다.

| 기준 | 기존 레코드 기준 결과 |
|---|---|
| 중요 5종 합산 Recall 기준선 이상 | 수치상 통과 |
| 전체 F1 기준선 이상 | 수치상 통과 |
| 정상 오차단 증가 +1%p 이하 | 실패: +7%p |
| 중요 유형별 미해결 퇴행 없음 | 계좌·카드 퇴행 있음. 오차단을 고쳐도 별도 보류 사유 |
| 유효한 최종 시험·완결된 검사·dev 선택 | 미충족 또는 증거 부족 |
| B의 운영 수용 | 미확인. 실행기의 `runtime_acceptance=True`는 승인 증거가 아님 |

교체 기준은 PRD §6, 요구사항 추적은 §11을 따릅니다. 현재 M0 유지입니다. 과거 표본에서 M0가 정상 1/100을 차단했으므로 +1%p 허용은 M1 2/100까지를 뜻합니다. 새 시험에서는 새로 측정한 M0 기준으로 계산합니다.

## 5. 후속 작업은 8단계 패키징보다 7.5단계 보완입니다

1. 실제 소스·학습 인자·표본·epoch 저장본·로그·가중치 해시를 확보합니다.
2. 학습/예측 분할과 검사 상태 처리, 비교 조건·캐시·예측 보존을 수정합니다.
3. 기존 저장본부터 dev에서 평가하고 M0/M1의 임계값을 같은 절차로 선택합니다. 정상 조정 자료는 최종 시험과 분리합니다.
4. 오차단과 계좌·카드 미탐을 분석하고 필요한 경우에만 새 실험으로 재학습합니다.
5. 새 서비스 holdout을 선택 과정 전에 사람 검토·동결하고, 선택 완료 후 공식 test와 함께 최종 평가합니다.
6. 규칙 결합·잔존율·실패·CI를 포함해 판정하고 보고서·그래프를 만듭니다. M1 미달 시 M0 유지 결과를 기록합니다.

정상 예시 부재는 확인된 데이터 특성이나 오차단 증가의 유일한 원인으로 입증되지 않았습니다. 임계값 0.65~0.7로 즉시 1% 이하가 된다는 주장도 검증되지 않았습니다. 현재 규칙 결합은 모델 findings에 규칙 findings를 더하므로 모델 오탐을 자동 제거하지 않습니다.

[전체 체크리스트](../stage7_5.md)를 따릅니다. 기준을 통과한 후보의 패키지·서비스 적용은 B의 계약 및 실제 인수 검증과 연결합니다.
